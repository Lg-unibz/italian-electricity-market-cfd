# Reproducibility protocol

This document describes the complete local workflow for rebuilding the
preprocessing baseline and the historical CfD backtest.

## 1. Environment

The paper reference environment is Python 3.14.0. Install the exact dependency
versions recorded in the lock file:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-lock.txt
```

Set the source path for direct execution:

```powershell
$env:PYTHONPATH = "src"
```

## 2. Acquire inputs

Follow `data/README.md` and `data/source_manifest.csv`. GME files are obtained
from the historical zonal-price portal. Terna files are downloaded through the
included adapter where an API endpoint is available. Copernicus retrieval
requires a CDS account and acceptance of the dataset terms.

Download the annual Terna capacity and production files with:

```powershell
python -X utf8 scripts/fetch_terna_historical_wind.py
```

Download the optional geographic layers with:

```powershell
python -X utf8 scripts/fetch_istat_boundaries.py
python -X utf8 scripts/fetch_natural_earth_admin1.py
```

Retrieve and normalise Copernicus ADM1 archives with:

```powershell
python -X utf8 scripts/fetch_copernicus_wind_archives.py
python -X utf8 scripts/prepare_copernicus_wind.py
```

The normaliser maps 110 coded Italian ADM1 units to 20 regions using
geodesic-area weights. It writes the canonical long-form CSV expected by the
backtest.

## 3. Run and validate

Run the offline tests first:

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -v
```

Run the 2024 preprocessing pipeline:

```powershell
python -X utf8 scripts/fetch_terna_wind_data.py
python -X utf8 scripts/run_pipeline.py
```

The pipeline writes auditable CSVs and diagnostic figures under
`data/processed/`. It checks 8,784 Europe/Rome delivery hours per 2024 zone,
capacity-factor bounds, and the known Terna source-hour gap.

Run the complete historical comparison:

```powershell
python -X utf8 scripts/run_historical_cfd_backtest.py
```

Use `--skip-maps` if ISTAT boundaries are unavailable. Results are written to
`results/historical_cfd_backtest_2015_2024/`.

Verify input and output hashes against the reference run:

```powershell
python -X utf8 scripts/verify_reproduction.py
```

The verifier covers all runtime inputs, all 21 preprocessing outputs, and all
28 historical-backtest outputs. A mismatch is a failed reproduction even when
the pipeline itself exits successfully.

If the manuscript source is available, run:

```powershell
python -X utf8 scripts/verify_manuscript_consistency.py `
  --manuscript path/to/main.tex
```

This checks the eight referenced figures, calibration and technology-selection
tables, all 20 regional Value Factor rows, all 80 regional map-source rows,
the complete regional-results appendix, distribution statistics, robustness
flows, and the main numerical claims.

## 4. Reproducibility notes

- The empirical unit is a stylised 1 MW regional proxy asset, not an individual
  metered wind farm.
- Prices are converted to real 2024 EUR/MWh using the Italian annual-average
  HICP values embedded in the input module.
- Terna annual data provide capacity weights and an external production check;
  Copernicus/ERA5 supplies the homogeneous hourly wind profiles.
- The historical mapping assigns Umbria to Centro Nord and Calabria to Sud
  through 2020, then applies the seven-zone configuration from 2021.
- No NPV, ROI, future-price scenario, stochastic extension, or original hybrid
  mechanism is generated by this release.

For the full equations, assumptions, and output contracts, read
[`historical_cfd_backtest.md`](historical_cfd_backtest.md).

## 5. Zenodo data deposit

The normalized Copernicus input is redistributable under CC BY 4.0 but is too
large for ordinary GitHub tracking. GME and Terna raw files are excluded from
redistribution. After reproducing the outputs, build the separate data record:

```powershell
python -X utf8 scripts/build_zenodo_data_deposit.py
```

Upload the generated files under `release/zenodo-data-v1.0.0/` to a Zenodo
dataset record, publish it, then add its DOI to `.zenodo.json`,
`CITATION.cff`, and the manuscript Data Availability section before creating
the final GitHub release.
